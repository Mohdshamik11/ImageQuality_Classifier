00

Summary

What was built, and what four rounds of diagnosis-driven changes bought.

The goal was to learn how a machine-learning project actually works by building one end to end: a from-scratch CNN that multi-label-classifies images for quality defects, with a future image-enhancement phase in mind. No transfer learning — the point was the fundamentals.

There is no public dataset of photos labelled “blurry” or “underexposed,” so the dataset was synthesised: 750 clean photos from COCO were each degraded five ways with controlled image maths, giving 4,500 single-defect images plus a matched clean copy of every scene. The split, the labels, and a small set of deliberately multi-defect test images were all designed to keep the evaluation honest.

The first model scored a respectable macro-F1 0.85 on single-defect images but collapsed on stacked defects (0.53), and one class — noise — lagged the rest badly. Each of the next three iterations targeted one diagnosed problem. The final model was measured once on the held-out test set: macro-F1 0.911 on single-defect images (validation had predicted 0.909 — the two agree, which is the sign the iterations were principled and not fitted to the validation set) and 0.883 on the multi-defect probe. Noise is recovered and the overfitting gap is essentially closed.

The model is wrapped in a Streamlit app (imagequalityclassifier.streamlit.app): upload photos, each is classified by tiling a 256-pixel window across the whole frame, and an “Enhance” button runs a classical, flag-driven repair on the ones with defects. Classical repair of noise and blur is limited by design; section 11 is the staged plan to make it reliable.

01

The task & why these choices

Four decisions were fixed up front. Each has a reason that shaped everything downstream.

Multi-label, not multi-class

A single photo can be blurry and underexposed and noisy at the same time. The five defects are not mutually exclusive, so the model has five independent yes/no outputs, each with its own sigmoid — not a single softmax that forces one winner. Conceptually it is five detectors sharing one feature-extraction backbone.

A CNN trained from scratch

Transfer learning was ruled out deliberately. The defects here are low-level visual statistics — the presence or absence of high-frequency edges, the spread of the brightness histogram, the amount of random pixel-to-pixel variation — not object semantics. A shallow network is genuinely well-matched to that, and building it from nothing is where the learning is.

Labels in a CSV, not folders

Folder-per-class cannot represent an image that belongs to two classes. The labels live in a single CSV with one binary column per defect (filename,blur,underexposed,overexposed,noise,contrast); a clean image is a row of zeros, a two-defect image has two ones. This is the mechanism that makes multi-label possible at all.

Built with a phase 2 in mind

A later phase will attempt to repair each detected defect. Every pipeline decision was checked against that: the degradation functions are written as standalone image → image transforms so they can be reused to generate training pairs for a restoration model later.

02

Data pipeline

Four scripts, run in order: source → degrade → split → add stacked-defect probes.

Source images — download_raw_images.py

750 photos were sampled from the COCO val2017 set and filtered to be clean baselines: minimum dimension 300 px, mean brightness between 40 and 220, and a Laplacian-variance sharpness above 60. The synthetic defect must be the only source of degradation, so anything already dark, blown-out, or soft was rejected.

Synthetic defects — generate_synthetic.py

Each raw image produces six outputs: one untouched clean copy plus one image per defect. 750 × 6 = 4,500 images (~2.0 GB, saved as PNG so lossless — JPEG re-compression would add its own artefacts and muddy the noise class). Severity is randomised per image within a range, so the model learns “blur, generally” rather than “blur at exactly one strength.” Everything is seeded.

The five degradations. All maths is done in float, then clip(0, 255), then cast back to 8-bit — an unclipped cast wraps, turning a bright pixel black.
DefectOperationKnob & rangeWhy this operation
blurGaussian blursigma 1.0 – 4.0weighted neighbourhood average; models lens defocus better than a box blur
underexposedpixels × factor0.30 – 0.60multiply, not subtract — low light scales light proportionally, it doesn't crush shadows to black
overexposedpixels × factor, then clip1.60 – 2.60the clipping at 255 is the blown-highlight look
noiseadd zero-mean Gaussiansigma 8 – 30each pixel nudged up or down at random; models high-ISO sensor grain
contrastmean + (px − mean) × factor0.30 – 0.60pull every pixel toward the image's average brightness — compresses the histogram, the definition of low contrast

Train / val / test split — split_dataset.py

The split is done at the scene level, not the image level. All six variants of raw_0123 come from the same photograph — same objects, same composition. If raw_0123_blur.png were in training and raw_0123_noise.png in validation, the model would have effectively seen that scene during training, and the validation score would be inflated. This is group leakage, and the fix is to assign each of the 750 scene IDs to exactly one split.

A seeded shuffle of the scene IDs, cut 70 / 15 / 15 → 525 / 112 / 113 scenes = 3,150 / 672 / 678 images. The script asserts the three ID sets are disjoint before writing.

Multi-defect probe images — generate_combos.py

Training images are kept to one defect each — simpler to generate and label. But real bad photos stack defects: low light raises sensor noise; darkness hides softness. Whether a model trained on single defects generalises to combinations is a hypothesis, not a given, so validation and test each get 50 genuine multi-defect images (30 two-defect, 20 three-defect) as a held-out probe.

  • Generated only from scenes already assigned to val / test — the leakage rule still holds.
  • The impossible pair (underexposed and overexposed) is excluded → 9 valid pairs, 7 valid triples, covered round-robin.
  • Transforms are stacked in a fixed physical order: contrast → underexposed → overexposed → blur → noise. A real camera blurs at the lens, then the sensor adds noise on readout — blurring after noise would smear the grain and look fake.
  • A combo is not a new class. raw_0700_combo_blur_noise.png is simply a row with two ones.
Class balance Every scene contributes exactly one of each defect, so the classes are balanced against each other from the start (~17% positive each). Within any one class, “not present” outnumbers “present” about 5 : 1 — mild imbalance, and the reason plain accuracy is not used as a metric (a do-nothing model scores 83%).
03

The baseline model

Deliberately simple — a first architecture to beat, not a tuned one.

Four convolutional stages extract features; a small head turns them into five scores. Each stage is Conv 3×3 → ReLU → MaxPool 2: the convolution slides learned filters across the image, ReLU clips negatives to zero (so stacking layers isn't equivalent to one layer), and max-pooling halves the height and width.

Forward pass. Channels grow as spatial size shrinks — trading picture size for feature variety.
StageOperationOutput shape
inputRGB image3 × 256 × 256
conv 13→32, ReLU, pool32 × 128 × 128
conv 232→64, ReLU, pool64 × 64 × 64
conv 364→128, ReLU, pool128 × 32 × 32
conv 4128→256, ReLU, pool256 × 16 × 16
flatten—65,536
dense65,536→128, ReLU128
output128→55 logits

8,777,797 parameters — about 8.4M of them in that first dense layer (65,536 × 128). That is a lot of capacity relative to 3,150 training images, and it is the obvious place for the model to overfit. The plan was to watch the loss curves and only address it if they showed it.

The model outputs raw scores (logits), not probabilities. BCEWithLogitsLoss applies the sigmoid internally, per class, in a numerically stabler way; probabilities are taken with an explicit sigmoid only at evaluation. Optimiser: Adam at 1e-3, batch size 32.

04

How the model is judged

Accuracy is misleading here. These are the metrics that fit a multi-label, mildly imbalanced problem.

Computed per class, then summarised.
MetricQuestion it answersRole
precisionwhen the model says “defect,” how often is it right?punishes false alarms
recallof the images that really have the defect, how many are caught?punishes misses
F1balance of the two aboveper-class summary
macro-F1plain average of the five per-class F1sheadline number for comparing versions
PR-AUCare the model's probabilities ranked well, regardless of the 0.5 cutoff?diagnostic — see below
subset accuracyfraction of images with all five labels exactly rightstrict sanity check

PR-AUC earned its place as the key diagnostic. F1 is measured at one fixed threshold (0.5). PR-AUC ignores the threshold and asks whether, if you sorted every image by its predicted probability, the truly-defective ones would sit near the top. That distinction is what separates two very different failures:

  • Low PR-AUC and low F1 → the model genuinely cannot see the defect. Fix the data or the features.
  • High PR-AUC but low F1 → the model can see it; the cutoff is just in the wrong place. Cheap fix.

Twice in this project the second pattern appeared, and reading it correctly is what pointed to the right next step both times. Plain accuracy and micro-F1 are deliberately not reported — the first is dominated by the easy “no defect” majority, the second is redundant when the classes are balanced.

05

Four iterations

Each round changed one thing, aimed at one diagnosed problem, and was compared on the validation set. The test set was never touched.

Iteration 1

Baseline

resize · 10 epochs
Setup
The architecture above. Images resized (squished) to 256×256, pixels scaled to [0,1]. No augmentation.
Result
Single-defect validation macro-F1 0.853. Multi-defect macro-F1 0.530. Every class landed at F1 0.83–0.94 except noise, at 0.700 — and noise was the only class whose PR-AUC (0.79) was also low.
Read
Three problems. (a) Noise is weak on every metric including PR-AUC — a genuine signal problem, not a threshold one. (b) Mild overfitting: training loss 0.07 against validation loss 0.23 at epoch 10, with validation flat since epoch 4. (c) On multi-defect images, precision is a perfect 1.00 but recall is 0.41 — the model detects stacked defects (PR-AUC stays high) but its confidence sits below 0.5, so they read as misses.
Root cause
Why noise specifically? The last step before the model resized ~600 px photos down to 256. Downscaling averages neighbouring pixels, and averaging is exactly how you remove random noise. Noise is the one defect the pre-processing destroys.
Iteration 2

Grain-preserving crop

crop · 10 epochs
Change
Replace “squish to 256×256” with “resize the short side to 256, then take a 256×256 crop” — a random crop for training (which doubles as augmentation), a centre crop for val/test. A crop keeps native pixel detail, so the grain survives.
Why
Directly targets the diagnosed root cause. The maths that erased the noise was the aggressive resize; a crop barely resizes at all.
Result
At the 0.5 threshold, a wash: macro-F1 0.845 vs 0.853, noise F1 slightly down at 0.675. But noise PR-AUC rose 0.79 → 0.83, blur and contrast PR-AUC also rose, and the overfitting gap narrowed from 3.2× to 2.4×.
Read
The random crop is augmentation, so the model overfits less → it is less overconfident → its probabilities drift below 0.5 across the board (macro-precision up, macro-recall down). The signal improved; the threshold is now in the wrong place. “Good ranking, wrong cutoff.”
Iteration 3

Per-class threshold tuning

no retraining
Change
For each class, sweep the decision threshold 0.05–0.95 and keep whichever value maximises that class's F1 on the validation set. No retraining — it re-uses the probabilities the model already produced. Run on both the baseline and the crop checkpoint, so the comparison is tuned-vs-tuned.
Why
Iteration 2 left an open question: was the crop's PR-AUC gain real, or noise? A threshold sweep converts a better ranking into a better F1 — if the ranking genuinely improved, tuning will show it.
Result
The crop model wins on every metric once both are tuned. The decisive detail: the baseline's noise F1 could not be improved by any threshold (0.700 → 0.700, identical) — its ranking was too jumbled. The crop model's noise F1 tuned up to 0.746, because its better ranking had something to work with.

Iteration 4

Stacked defects in training

crop + 525 train combos · 15 epochs
Change
Add 525 multi-defect images to the training set (from training scenes only), and train for 15 epochs instead of 10. Same architecture, same crop pipeline.
Why
On multi-defect images the model's noise PR-AUC was 0.91 — the ranking was excellent — but its F1 was ~0.36. High PR-AUC, low F1: not a visibility problem, a calibration problem. The model's confidence collapsed on stacked defects because it had only ever trained on single ones. The fix is to show it stacked defects.
Result
Single-defect macro-F1 0.909, multi-defect macro-F1 0.905. Noise F1 rose to 0.88 on single-defect images and 0.88 on multi-defect (from 0.07–0.36). Overfitting essentially gone: training loss 0.097 against validation loss 0.110 at the best epoch — a 1.1× gap, down from 3.2×.
Threshold
Tuning now buys almost nothing (+0.008 on single-defect, −0.009 on multi-defect — one threshold set can't serve both). The shipped model uses a plain 0.5 for every class, which also avoids a “thresholds were fitted on validation” caveat.
Caveat
This round changed two things (combos and epoch count). The multi-defect gains are almost certainly the training combos — extra epochs cannot teach stacked defects — but the single-defect noise gain is partly the extra noise data and partly the longer schedule.

07

The application

A Streamlit app around the frozen model: classify uploaded photos, then repair the flagged defects.

Scanning the whole frame — tiling

The model was trained on 256×256 crops of images with globally uniform defects. A real upload breaks both assumptions: it can be 12 megapixels, and its blur may be local — a sharp subject on a soft background. Feeding it a single centre crop would mean the model only ever sees the middle of the photo.

Instead, inference tiles: resize the upload's short side to 320 px (close to the training scale — a larger resize would zoom the tiles in and shift how blur and grain look), slide a 256×256 window across it with ~60% overlap, score every tile, then combine. A typical photo yields 4–10 tiles; hard-capped at 16. No retraining — the crop-augmentation from iteration 2 is exactly what makes the model expect 256-pixel patches.

The tiles are combined per defect, along the taxonomy:

  • blur is local → take the maximum tile probability: “is there blur anywhere in the frame?”
  • underexposed, overexposed, noise, contrast are global → take the mean: a global property shows up in every tile, and one odd tile should not flip the call.

The interface

Upload up to 15 photos (a RAM cap for a free CPU host; larger uploads are downscaled on ingest). Each is classified once, on arrival, and shown as a card with a 2 flagged / clean summary; the five per-class probabilities stay hidden behind a compact expander until the card is opened. An “Enhance” button then repairs every photo with at least one flag and shows the before/after with a download.

Enhancement — classical and flag-driven (phase 2a)

The enhancer reads the classifier's five flags and applies only the corresponding fix — the classification is what steers the repair. Every fix is blind auto-correction (real uploads weren't degraded by our scripts, so there is no known factor to undo), its strength scales with the classifier's confidence (a detection right at 0.5 barely touches the image; a 0.95 gets the full moderate fix), and the tonal fixes work on the lightness channel only so colours don't shift.

Order matters: contrast stretch and sharpening both amplify noise, so denoise sits between them and sharpen runs last.
FlagFixTechnique
underexposedbrightengamma correction, gamma 1.0→0.6
overexposedtone downgamma 1.0→1.5 (pixels clipped to white are unrecoverable)
contrastexpand tonal range1st–99th percentile histogram stretch, blended by strength
noisedenoisenon-local means (cv2.fastNlMeansDenoisingColored)

Honest limit Exposure and contrast come out genuinely fixed. Noise and blur are only nudged — classical methods can't invent detail. Unsharp mask re-weights the edge energy that survived; it can't restore frequencies the blur destroyed. Non-local means removes grain but softens texture with it. Professional-grade repair needs a learned restoration model — section 11.

09

Reproducibility

Everything is seeded (42) and scripted.

Data pipeline, in order:

  • src/download_raw_images.py — COCO subset → data/raw/
  • src/generate_synthetic.py — degradations → data/synthetic/ + labels.csv
  • src/split_dataset.py — adds the split column, scene-level
  • src/generate_combos.py — multi-defect probes; --n-train 525 adds the training combos

Reusable modules: src/dataset.py (the Dataset and loaders; augment=True switches on the crop pipeline), src/model.py (BaselineCNN), src/metrics.py (per-class metrics, PR-AUC, tune_thresholds).

Each iteration is a notebook — 01_baseline, 02_crop, 03_threshold_tuning, 04_train_combos — that writes its checkpoint and per-epoch history to models/. Earlier notebooks are left frozen as the reference for each stage.

The app: src/predict.py (tiled inference → per-defect probabilities), src/enhance.py (the five classical fixes + a flag-driven orchestrator), app.py (Streamlit, main file for deployment). The frozen model is models/traincombo_best.pt.

Environment: conda (imageQuality_Classifier), PyTorch on a single RTX 3050. A full training run is a few minutes; app inference runs on CPU.

10

Limitations

What this project is not.

The classifier

  • The multi-defect probe is no longer a pure generalisation test. Once combos entered training, the val/test combos measure “does combo training transfer to unseen scenes,” not “does single-defect training generalise for free.” Both are valid; the claim changed.
  • Noise is still the weakest single-defect class (test F1 0.843) and overexposed the weakest on stacked defects (test F1 0.824, recall 0.70).
  • Synthetic defects are globally uniform and Gaussian. Real photos have localised blur and blown highlights, and real noise and blur (motion, defocus, demosaicing, compression) differ from the clean Gaussian synthetics. Tiling handles the “local” part; the “different kind of degradation” part means the model generalises to real photos only partway.
  • Iteration 4 is confounded (combos + epochs). A clean 15-epoch re-run of iteration 3 would disentangle them; skipped on time grounds since the direction is unambiguous.

The enhancement

Phase 2a is classical, and classical repair of noise and blur has a hard ceiling: it cannot invent detail. Exposure and contrast come out genuinely fixed; noise and blur are only nudged. The concrete plan for reliable repair is section 11.

Deployment: Streamlit Community Cloud (free, CPU, ~1 GB RAM) at imagequalityclassifier.streamlit.app. The 15-image cap and CPU-friendly model sizes are chosen for it.

11

Toward reliable enhancement

Phase 2a was deliberately the classical baseline. This is the staged plan to make the “Enhance” button actually reliable, in order of effort.

The classifier stays as-is throughout — it already tells the enhancer what to fix. What changes is how the fix is done: from hand-written image maths to a trained model with a learned prior over what clean photos look like.

Stage 1 — a small restoration network (the immediate next step)

  • Data already exists. Every raw_X_<defect>.png has a matching raw_X_clean.png, and the same for the combo images — that is a full set of (degraded → clean) training pairs, produced by the same generate_synthetic.py. Use the train-split pairs to train, the val/test pairs to measure.
  • Architecture: a small U-Net (encoder / decoder with skip connections), ~1–3M parameters, or a DnCNN-style residual net that predicts the noise/blur residual rather than the clean image. Either runs on CPU in ~1–2 s per tiled image, so the current tiling + Streamlit setup is unchanged.
  • Flag-driven still applies: either one network that repairs whatever it sees, gated on “any flag set,” or one small network per defect, each gated by its own flag. The per-defect option keeps the “only touch what is broken” guarantee.
  • Loss: L1 pixel loss to start; optionally add an SSIM term or a light VGG-feature (perceptual) term for sharper texture. Skip adversarial (GAN) loss at this stage — it is much harder to train stably.
  • Metrics: PSNR and SSIM against the clean target (these replace macro-F1 as the headline), reported on val/test pairs and on the combo pairs separately — the same held-out discipline as the classifier.
  • Expected result: clearly better than unsharp mask and non-local means — recovers plausible texture instead of over-smoothing — but not commercial “AI enhance” quality.

Stage 2 — realistic degradation modelling (what makes it work on real photos)

Stage 1 trained on clean single Gaussians will still under-perform on real uploads, because real degradation is messier: blur is motion + defocus + lens, noise is Poisson-Gaussian + demosaicing + JPEG compression, and they stack in random order and strength.

  • Replace the fixed synthetic transforms with a randomised degradation pipeline (the approach Real-ESRGAN uses): random blur kernels including motion, mixed noise models, JPEG re-compression, resize — applied in random order at random strength.
  • Train on a larger, more varied set — thousands of images, or established restoration datasets (DIV2K for general, GoPro for motion deblur, SIDD for real denoise).
  • This needs a GPU for training runs of days, not the few-minute runs the classifier needed.

Stage 3 — bigger architecture, or pretrained weights

  • Bigger from-scratch: a modern restoration architecture — Restormer (transformer-based) or NAFNet — trained with the Stage 2 pipeline. Near-professional, GPU-bound, months of work.
  • Pretrained, no training: load published NAFNet / Restormer / SCUNet weights and run inference only. Fastest path to genuinely professional output — but the models are 50–300 MB, need a GPU host, and dropping in someone else's trained network abandons the from-scratch premise of this project.

The hard limits — no method fixes these

  • Blown-out highlights. Pixels clipped to pure white lost their detail at capture. Unrecoverable by anything.
  • Perfect deblur. Deblurring is ill-posed — many different sharp images produce the same blurry one — so even Stage 3 output is a plausible reconstruction, not the true original.
Recommended entry point Stage 1. It reuses the existing synthetic pipeline and its data, stays CPU-deployable on the same free tier, is an honest incremental improvement over phase 2a, and keeps the project's story intact: one synthetic pipeline, a classifier and a restoration network both built from it.
